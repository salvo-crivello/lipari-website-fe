# lipari-website-fe

Corporate website rebuild for Lipari Consulting.

**What this is:** a portfolio-grade project. The primary objective is
showcasing senior React/TypeScript frontend engineering — architecture,
accessibility, performance, animation — not just shipping a brochure site.
Visual bar: IBM Consulting, Deloitte Digital, Accenture Song, Digital Design
Days.

**What's next (not now):** a Python backend + AI orchestrator (likely a
stateful chat widget) will be added later. Frontend-only for the current
phase — don't build scaffolding for the backend/AI parts yet.

---

## 1. Standing rule

> Every architectural decision should be something a Senior Front-End
> Engineer would make in a real enterprise project. Avoid tutorial-style
> architecture. Don't overengineer — keep it simple but highly maintainable.

This rule already produced the concrete decisions below. Don't re-litigate
them without the user explicitly reopening the topic.

| Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

| Tests colocated (`Button.tsx` + `Button.test.tsx`, same folder)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Rename/refactor moves both files together. Only `e2e/` stays top-level (Playwright, not colocatable by nature).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Path aliases mandatory (`@/components`, `@/content`, `@/lib`, ...)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | No `../../../../` relative import chains.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Env validation with Zod at boot (`lib/env.ts`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Crash immediately on a missing var instead of a silent runtime `undefined`. Complements, doesn't replace, `.env`/`.env.local` — those hold the raw values, `env.ts` validates/types them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Route-level `error.tsx` / `not-found.tsx` / `loading.tsx` per segment                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | No single global catch-all.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| No barrel `index.ts` re-export files                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Barrels cause circular deps and break tree-shaking at scale — import directly from source. (Exception: `utils/index.ts` _is_ the utils module, not a re-export barrel — see `docs/architecture.md`.)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| No global state manager for now                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Redux Toolkit rejected as overkill for a mostly-static site. If a stateful feature shows up later (e.g. the AI chat widget), reach for **Zustand**, not Redux Toolkit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Tailwind stays primary, not SCSS                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | SCSS was considered and rejected — it would lose the single source of truth for design tokens, purge, and consistency. If SCSS ever comes back, it's a colocated `.module.scss` next to the one component that needs it (complex keyframes, 3rd-party override) — never a full replace of Tailwind.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `type` only, never `interface`; every type alias is `T`-prefixed PascalCase (`Labels` → `TLabels`, `DeepPartial` → `TDeepPartial`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Enforced as ESLint rules (`@typescript-eslint/consistent-type-definitions` + `@typescript-eslint/naming-convention` in `eslint.config.mjs`), not just a convention — lint fails on a violation, it doesn't rely on review catching it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Type-only files end in `.types.ts`. Global/cross-cutting types (`types/labels.types.ts`) are lowercase; types colocated inside a component folder match that component's casing (`Button/Button.types.ts`, PascalCase)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Global types live in a shared folder addressed by concern, not by component — lowercase matches that folder's existing convention. Colocated types are siblings of the component file they describe, so they take its casing instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `components/ui/*` primitives (design-system components with variants, e.g. `Button`) get their own folder: `Button.tsx`, `Button.test.tsx`, `Button.types.ts`, `Button.styles.ts` (the `cva` variant definition, isolated from markup/logic)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | These are the shared visual contract of the whole site and tend to accumulate variants over time — separating style from logic pays off here. One-off `views/*/sections/` components don't get this treatment (no variants to isolate, would be overhead) — see `docs/architecture.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| No separate `ui/basic/` vs `ui/complex/` folders for compound components (e.g. a `Card` with `CardHeader`/`CardTitle`/`CardBody`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | The basic/complex boundary is fuzzy and churns as a component grows. A compound component just exports multiple named parts from its own folder (`Card/Card.tsx` exports `Card`, `CardHeader`, `CardTitle`, ...) — complexity is a detail inside the component's folder, not a routing decision between two top-level directories.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| One-off brand assets (e.g. `Logo`) live in `components/ui/brand/`, separate from reusable design-system primitives                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | A `Logo` isn't a primitive with variants meant for reuse across arbitrary contexts — it's a fixed brand asset. Keeping it out of the flat `ui/` primitives list avoids conflating "reusable design-system piece" with "the one logo the company has".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `Logo` accepts `width`/`height`/`className` directly (`TLogoProps = TSvgProps`, reusing the global type instead of a bespoke one), sizing its own root element — callers don't wrap it in an externally-sized `<div>`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | `TSvgProps` (`components.types.ts`) is the established shape for anything icon/logo-like, reused rather than redeclared. Default `80` (matches the original hardcoded `h-20 w-20`); `Header` passes `56` for the compact nav context.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Test files end in `.test.ts`/`.test.tsx`, never `.spec.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | User's explicit preference, applies to both unit tests (Vitest) and e2e (Playwright) — Playwright's default `testMatch` already accepts `.test.ts`, no config change needed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| React pinned to **18.3.1**, not 19                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Explicit user call — React 19 considered not yet stable enough for this project. Next.js 16's peer range (`^18.2.0 \|\| ^19.0.0`) allows this; `create-next-app` had defaulted to 19, that default was overridden.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Prettier: no semicolons, no trailing commas (`"semi": false`, `"trailingComma": "none"`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Explicit user preference. Applies everywhere Prettier formats, including `type`/`interface` member separators (Prettier respects `semi: false` there too, not just statement-level). Item-separating commas within one line (`{ a: 1, b: 2 }`) still appear — only the optional trailing one is dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Any `ui/*` component using **Motion** (`motion/react`) needs `"use client"` at the top of the file                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Motion relies on browser APIs — it cannot be evaluated during server rendering. The component itself becomes a Client Component, but its caller (e.g. a Server Component like `Header`) keeps fetching data server-side and just passes the resolved value down as a plain prop (a string, not `children`) — no need to convert the whole call site to client.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Server Components resolve `getLabels()`/other content fetchers and pass only the specific slice a Client child needs as a plain prop — never a raw `TLabels` blob, never `sessionStorage`/a global store for server-fetched copy. That prop is always named `labels`, typed via `TLabels[...]` indexed access — never a domain-specific name (`areas`, `cities`, `members`, ...) and never a hand-rolled parallel type for data that already exists in `TLabels`. Internal destructuring can still alias it to a readable local name for the function body (e.g. `{ labels: areas }`) — the rule targets the prop/attribute name, not every internal variable. Excluded: props that merge label text with non-label data (e.g. `Header`'s `items`, which pairs route `href`s with nav labels) — renaming those to `labels` would hide that they carry more than copy. | Keeps content fetching server-side (SEO, no flash-of-empty-content, single source of truth via Next's request memoization + ISR) while still letting individual interactive pieces (mobile menu, hover states) be Client Components — generalizes the Motion `"use client"` row above rather than inventing a second pattern for the same problem. The uniform `labels` name makes "this prop is content from `getLabels()`" recognizable at a glance across any feature file, and forcing the type through `TLabels[...]` indexed access means a fixture shape change is a compile error at every consumer, not a silent drift (caught after `TCity`/`TTeamMember` were found hand-rolled instead of derived). Concrete example: `Header.tsx` (server, fetches labels) → `HeaderShell.tsx` (client, owns `useWindowSize`/mobile-menu state), which receives resolved `items: { href, label }[]` (excluded — mixed data) and `labels: string` (the cta copy), never the whole `TLabels` tree. |
| Internal route paths are defined once in a `ROUTES` const (`constant/routes.ts`), everything else (`NAV_ITEMS`, `LEGAL_ROUTES`, ...) references `ROUTES.X` instead of repeating the literal path string                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Single source of truth for path strings — renaming a route means editing one line, not grepping for the literal string across every array that links to it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| A nav item for the current route is never rendered as a (fake-)disabled `ButtonLink` — the shared `useIsActivePath(href)` hook (`hooks/useIsActivePath.ts`, wraps `usePathname()`) plus `HeaderNavLink` (`components/layout/header/`) swap it for a static `<span aria-current="page">` reusing `buttonVariants` directly, instead of threading a disabled state through `Button`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | HTML anchors have no native `disabled` — faking it (`aria-disabled`/`pointer-events-none`/`preventDefault`) is a known a11y anti-pattern assistive tech doesn't handle consistently. Not rendering a link at all for "you are here" is both the correct semantics and less code. `HeaderNavLink` is shared by `DesktopMenu`/`MobileMenu` so the active-route match rule (exact for `/`, prefix for everything else) and the selected style live in one place, not duplicated per menu.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `Button.tsx` exports two things from one file: `Button` (default, `motion.button`) and `ButtonLink` (named, wraps `next/link`) — both consume the same `buttonVariants` from `Button.styles.ts` and share the `TButtonProps` shape (`text`, `icon`, `iconPos`) from `Button.types.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | A button that navigates and a button that acts are the same visual component with a different root element — splitting them into two files would duplicate the variant styling and prop shape for no benefit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `components/layout/MainComponents.tsx` holds generic `Header`/`Main`/`Section`/`Footer` layout primitives (padding, max-width, sticky positioning) — the real `components/layout/Header.tsx`/`Footer.tsx` compose their content inside these instead of writing raw `<header>`/`<footer>` tags                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Keeps the "same padding/max-width everywhere" rule enforced in one place instead of repeated per real header/footer.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| _Preference, not a hard rule:_ when building a new section or distributing a layout responsively, default to `flex` at mobile/base and switch to `grid` from `sm:` up — not one paradigm hardcoded across every breakpoint, and not grid-down-to-flex-up.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | User's stated default for new layout work. Mobile is usually a simple 1-2 axis stack that `flex` handles with less boilerplate than a 1-column grid; `grid` earns its keep once there's an actual 2D arrangement (columns + rows together) to control, which typically only shows up from `sm:` up. Deviate when a given breakpoint genuinely fits the other model better — this is a starting default, not something to force.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `Button`/`ButtonLink` have **3 independent `cva` axes**: `variant` = shape (`fill` \| `outline` \| `ghost` \| `text`), `color` = brand family (`primary` blue \| `secondary` green \| `tertiary` neutral/slate), `surface` = which background it sits on (`dark` \| `light`, default `dark`) — an icon (`icon`/`iconPos`) is addable to any combination                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | `variant` was never renamed to `type` — that would shadow the native HTML `button` `type` attribute already flowing through `TButtonHtmlProps`. Matches the MUI/Chakra convention (shape vs. color as separate props) rather than inventing a new naming scheme. `surface` exists so outline/ghost/text/tertiary-fill buttons pick the right contrast automatically instead of the caller manually overriding classes per background — solid `primary`/`secondary` fill doesn't need it, it's legible on both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

## 2. Stack

- **Framework:** Next.js (App Router) + React 18 + TypeScript
- **Package manager:** Yarn (node-modules linker, not PnP — avoids friction with Playwright/Husky/editor tooling)
- **Quality:** ESLint, Prettier, Husky, lint-staged, eslint-plugin-jsx-a11y (bundled via `eslint-config-next`, no separate plugin needed)
- **Testing:** Vitest, React Testing Library, Playwright
- **Styling / motion:** Tailwind CSS, Motion React _(do not drop — flagged explicitly by the user once already)_
- **Forms:** React Hook Form + Zod
- **UI utilities:** clsx, class-variance-authority, tailwind-merge, Lucide React (icons)

Next.js handles SEO/meta/prerendering natively via `generateMetadata`
(including on dynamic routes) — no react-helmet needed.

**Design tokens** (`app/globals.css`, Tailwind v4 `@theme`, no `tailwind.config.ts`):
`brand-green`/`brand-blue` each have a full `50`-`950` scale plus a bare
(no-number) alias resolving to their `500` — `brand-blue-500` is
`#2F54D9` (the design-given value), `brand-blue-950` is `#001A29`
(anchored to the navy already used sitewide, not purely algorithmic — the
two other steps between were interpolated between those two real anchors).
`brand-green-500` is `#9BE868`. Bare `--color-brand-blue`/`--color-brand-green`
(no suffix) are separate CSS vars pointing at the same value as `-500`, not
an alias — that's what makes `bg-brand-blue` work without a number, since
Tailwind v4 has no v3-style `DEFAULT` key.

## Behavioral Guidelines

1. **Think Before Coding** — read the relevant section above (and its
   chained doc) before touching a file; this project's structure encodes
   deliberate decisions, not defaults.
2. **Simplicity First** — match §1's standing rule: no overengineering, no
   scaffolding for the not-yet-built backend/AI parts.
3. **Surgical Changes** — respect the layering and dependency rule in
   `docs/architecture.md`; don't introduce sideways or upward imports.
4. **Goal-Driven Execution** — this is a portfolio piece; changes should
   move it toward the stated visual/engineering bar, not just toward
   "done."
